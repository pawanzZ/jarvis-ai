## 2. Logic Chain

1. **Step 1 (Event Bus Process Loop Reliability):**
   - By isolating individual handler execution in `try...except Exception:` within `EventBus.process()`, exceptions generated by buggy, crashing, or throwing plugin event handlers cannot propagate to the top-level loop.
   - The queue processor remains alive indefinitely and continues dispatching remaining handlers for the current event and all subsequent events.

2. **Step 2 (Plugin Lifecycle Resilience):**
   - By isolating exceptions in `plugin.stop()` inside `deactivate()` and `stop_all()`, a failure in one plugin during shutdown does not prevent other active plugins from being gracefully stopped.
   - Removing the plugin from `_active` in a `finally` block ensures internal state consistency.

3. **Step 3 (Protocol Gateway Alignment):**
   - Adhering strictly to `PROJECT.md` WebSocket gateway specifications allows the frontend HUD (Milestone 3) and external clients to send standard messages (`activate`, `deactivate`, `config_update`, `ping`, `settings_request`) with bidirectional reliability.
   - Malformed JSON and primitive JSON types are rejected with structured error frames rather than dropping websocket connections.

4. **Step 4 (Config Namespace Cleanliness):**
   - Retaining only relative path stems in `list_namespaces()` eliminates phantom namespace entries for nested plugin configs, ensuring `config.get(namespace)` always maps correctly to valid disk files.
